# Kitmux v0.2 — live local MCP control

The original roadmap's next milestone is local stdio lifecycle control. The
v0.1 bridge already provides per-connection supervision; v0.2 builds on it rather
than adding a permanent background daemon or changing the catalog format.

## Acceptance and affected areas

- [x] Read-only authenticated process diagnostics distinguish desired policy,
  bridge connections, actual upstream processes, and unverified client refresh.
  Cover idle/active/disabled/exited and multiple independent connections without
  launching upstream as a side effect. (`runtime_control`, `runtime_status`)
- [x] Tools-only legacy negotiation accepts supported upstream-selected versions;
  cancellation/progress remain scoped to accepted calls. Preserve session metadata,
  reject stale calls while disabled, and never replay interrupted operations.
  (`runtime_protocol`, `runtime_spawn`)
- [x] Scriptable `mcp status ID --agent AGENT [--json]` and general status expose
  the observed process state while preserving policy explanations. (`mcp`, `status`)
- [x] The TUI supports direct/managed local mode selection, per-client reconnect,
  and explicit refresh of a captured process-status view. (`tui`)
- [x] Record actual installed-client qualification results using temporary homes,
  local fixture MCPs, and no live accounts. Distinguish native observations from
  synthetic protocol coverage and document remaining acceptance gaps.
- [x] Imported Codex stdio definitions can switch between direct and managed mode,
  retaining native policy, environment settings, comments, and exact restore.
- [x] Full integration and PTY suite, ASan/UBSan, usage docs, and independent review.

## Verification approach

The v0.1 characterization baseline is 63 passing tests in both `make test` and
`make -j4 sanitize`. Add failing behavior tests for
each v0.2 contract before implementation. Reuse fixture processes and temporary
homes. Native client probes must isolate HOME/XDG/config/auth and avoid models or
accounts unless a credential-free local fixture supports the full path.

## Risks and rollback

Socket existence alone is not evidence of a running process. Diagnostics query
authenticated peers and never control unrelated processes. Read-only queries must
not trigger discovery or restart. A running upstream does not prove a client's
tool catalog refreshed. Keep these observations distinct in the UI and commands.

Retain the v1 catalog and existing ownership journal. Existing direct MCPs remain
direct unless explicitly edited. Reverting to v0.1 requires no catalog migration;
the native restore command remains available for adopted configurations.

## Progress and evidence

Core verification on macOS arm64:

- `make -j4 test`: **101 passed, 3 opt-in native tests skipped** (104 total).
- `make -j4 sanitize`: **101 passed, 3 opt-in native tests skipped** (104 total),
  with AddressSanitizer and UndefinedBehaviorSanitizer; no reported errors.
- `make test-native`: **3 passed, no skips** through installed Codex, Claude Code,
  and OpenCode processes. All three exercised discovery/call, live disable,
  stale-call rejection, re-enable, and reconnect in isolated fixture environments.
- Manual colored TTY check: opened Status, captured a new observation with `f`,
  scrolled, and exited with terminal restoration.

Observed Red failures included absent status routing and writer-lock bypass,
missing terminal selectors/snapshot refresh, rejected supported upstream revision,
dropped progress, unscoped cancellation, malformed protocol acceptance, blocked
imported Codex mode transitions, and an incorrectly complete timed-out scan.
The C shutdown fixture reproduced an upstream remaining alive while downstream
error output was blocked. The fix stops/reaps the owned process group first and
ends failure reporting after the first write failure.

Independent reviews covered protocol state, process ownership, time bounds,
configuration preservation, CLI parsing, and status privacy. They led to the
shutdown and scan fixes. Test harness/build targets and release documentation
were the test-first exceptions.

## Retained limits

The managed bridge is tools-only, local stdio, with legacy lifecycle revisions
through `2025-11-25`. HTTP/OAuth, resources/prompts, session-bound integrations,
modern stateless lifecycle, and initialization instructions require direct mode.
Cancelled calls retain bounded records until completion/reconnect. Upstream
stderr is discarded. Existing native settings can still require a client reload.

Status is a captured observation, bounded to 500ms and 64 candidate endpoints per
MCP/client. `scan_complete: false` distinguishes an incomplete observation; counts
exclude endpoints skipped after the budget. PIDs do not prove client tool refresh.
Linux and distribution artifacts remain the next roadmap milestone.

Imported Codex edits support single-line command/argument values and recognized
key layouts. Unsupported multiline changes fail closed, retaining native bytes;
the catalog reports pending sync and can be switched back to direct mode.

Exact installed versions, client surfaces, and native refresh timing are recorded in
[NATIVE_CLIENT_QUALIFICATION.md](NATIVE_CLIENT_QUALIFICATION.md).
