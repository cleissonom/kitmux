# V0.3: custom subagent management

Kitmux 0.3.0 adds custom subagents to the C17 CLI and terminal interface for
Codex, Claude Code, and OpenCode. Production behavior remains C; Python supplies
isolated verification fixtures only. No new application dependencies were added.

## Available controls

- Create portable profiles from Markdown instructions and a description, or add
  a native Codex TOML, Claude Markdown, OpenCode Markdown, or OpenCode JSON profile.
- Import existing user profiles, including different native definitions with the
  same ID in different clients. `subagent import` adopts only profiles; ordinary
  `import` also adopts MCPs and skills.
- Edit common instructions or a client's native variant, duplicate without
  assignments, remove, and enable/disable globally or per client.
- Include `subagent:ID` in mixed groups. Explicit client off and global off win;
  `inherit` returns a client to group policy.
- Preview and apply native projections, detect external edits, and restore the
  original definitions. Status separates compatibility, desired availability,
  native runtime ownership, and unverified refresh.
- Use the Subagents tab (`4`) alongside Groups, MCPs, Skills, Clients, and Status.
  `n` creates, `x` edits, `p` duplicates, `i` imports, and `a` assigns clients.

New portable profiles use the client's native defaults. Native imports are
available only to clients with an explicit variant; Kitmux does not translate
models or discard restrictions to make them portable. Shared edits preserve
native options and comments. Recognized Claude skill/MCP references are reported
as available, unavailable, or unresolved outside the managed catalog, without
automatically granting access.

## Persistence and safety

The first saved subagent upgrades a v1 catalog to v2. The ownership journal uses
v2 when it owns subagent files or JSON entries. V1 data is still readable; reads
alone do not migrate files. Older Kitmux builds reject v2 records, so use v0.3 or
newer for recovery and restore.

Imported definitions retain exact originals in the private ownership journal.
No-op import/sync preserves differing per-client prompts and native settings.
Regular files are written atomically; interrupted multi-file sync keeps a pending
journal and detects conflicting edits on retry. This is recoverable application,
not an atomic transaction across every client file.

OpenCode JSON profiles stay in native `agents` entries, including duplicates;
their `disabled` flag is managed without removing comments or other options.
Markdown/TOML profiles leave discovery when disabled. Switching an already-owned
OpenCode profile between Markdown and JSON is rejected before catalog mutation.

## Verification

`make -j4 test` and `make -j4 sanitize` each passed **189 tests**, with six opt-in
native cases skipped. `make test-native` passed all **six native cases** with no
skips. The diagram self-check and bundled skill validator also passed. Full
results are recorded in [architecture and verification](IMPLEMENTATION.md).

Red tests preceded implementation for absent CLI/TUI controls and profile import.
Additional failing regressions covered Unicode YAML offsets, aliased metadata,
invalid UTF-8/NUL input, generated and imported JSON location changes, unsafe
ownership records, native-name collisions, and nested discovery bypasses.
Documentation and native protocol harness creation were test-first exceptions.

The ordinary suite exercises catalog migration, every policy layer, definition
editing and duplication, native variants, preview/apply/restore, conflict and
pending recovery, malformed inputs, and keyboard journeys. Sanitizer builds run
the same suite with AddressSanitizer and UndefinedBehaviorSanitizer.

Installed-client qualification uses Codex 0.167.1, Claude Code 2.1.322, and
OpenCode 2.1.4 in temporary homes:

- Codex exposes the generated profile in a real app-server session's model
  context. A local Responses fixture completes the turn; fresh sessions prove
  disappearance after disable and rediscovery after re-enable.
- Claude discovers and selects the generated profile, includes its instructions
  in the synthetic provider request, and rejects the disabled profile before a
  provider request. The macOS sandbox blocks live home/keychain reads and remote
  traffic; `--bare` cannot serve this test because it skips profile discovery.
- OpenCode's location-scoped native agent list discovers both Markdown and JSON
  profiles, removes them after disable, and rediscovers them after re-enable in
  the same isolated server. Its initial list can be empty before config loads;
  the test waits for native readiness.

No live account, billed model, or production MCP is used by these tests. Existing
managed MCP lifecycle qualification remains part of `make test-native`.
See [native qualification](NATIVE_CLIENT_QUALIFICATION.md) for reproduction.

## Scope and limits

- User scope only. Project, plugin, and organization definitions retain native
  precedence. Disabling a custom profile does not disable a built-in fallback
  with the same name, stop running tasks, or erase their existing context.
- Flat regular-file collections with matching filename/native IDs are supported.
  Nested collections, symlinks, and OpenCode's legacy singular `agent` directory
  require explicit migration; guards prevent silently shadowing those sources.
- Keep an owned OpenCode profile in its current storage format. Use a separate
  profile ID when moving between Markdown and JSON.
- Native settings are preserved, but Kitmux cannot certify that every model or
  restriction is supported by every installed client. Codex inherits parent
  sandbox/approval/provider/MCP settings even if such fields occur in a profile.
- Native tests cover discovery, selection, and disable/re-enable. They do not
  certify delegated task execution or all project/plugin precedence combinations.
- Qualified on macOS arm64. Linux and other installed-client versions remain
  unqualified. Claude's opt-in profile test currently requires macOS sandbox-exec.

Existing native profiles are adopted explicitly. Preview discovered profiles
before applying an import:

```sh
kitmux subagent import --from codex,claude,opencode --preview
kitmux subagent import --from codex,claude,opencode --apply
```

[Claude subagents](https://code.claude.com/docs/en/sub-agents), and
[OpenCode agents](https://opencode.ai/docs/agents/).
