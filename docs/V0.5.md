# Kitmux v0.5 — resource documents and downloadable executables

V0.5 adds readable resource documents and a four-target macOS/Linux release
pipeline. Catalog schema 3 and existing CLI JSON formats remain compatible with
v0.4. Native ownership, credential preservation, availability, and restore rules
remain in force.

## Resource documents

Enter or `v` on a resource opens its document. Enter on a group still expands or
collapses it; `v` on a group retains its availability explanation.

- Skills show the complete installed `SKILL.md`, with source and revision metadata.
  They read the stored package, so edits to an upstream source do not change the
  displayed installed revision.
- Subagents show shared description/instructions and labeled effective client
  variants. Native model, environment, permission, and authentication fields are
  not dumped into the document.
- MCPs show their Markdown description, transport, runtime mode, and availability.
  Existing entries without a description show guidance to add one. Endpoint
  arguments, environment values, and native authentication snapshots stay hidden.

Use arrows or `j`/`k` to scroll, Page Up/Down or Space to page, and Home/End or
`g`/`G` to jump. Enter, Esc, or `q` returns to the original selection. Documents
wrap to terminal width and reflow after resize. Headings and fenced code receive
terminal formatting; lists and other inline Markdown remain readable source text.
This is a bounded terminal reader, not a full CommonMark renderer or browser.

The reader accepts skill files up to the existing 8 MiB file limit. Generated
subagent documents are bounded to four such bodies plus metadata. Documents are
independent of the command-output capture buffer's 32 KiB limit. Control sequences
are sanitized, and reading never executes commands, fetches remote documentation,
starts an MCP server, or writes catalog/native state.

## MCP documentation

```sh
kitmux mcp add docs --url https://example.invalid/mcp --description "Search docs"
kitmux mcp edit docs --description-file ./docs-guide.md
kitmux mcp edit docs --description ""
kitmux mcp edit docs --from ./docs-codex.json --format codex \
  --description-file ./docs-guide.md
```

Use either `--description` or `--description-file`. Input must be bounded UTF-8
text without NUL bytes. Empty text explicitly clears documentation. The TUI offers
keep/skip, text, Markdown file, and clear choices. Metadata-only edits preserve
execution variants and native settings; identical edits do not advance the catalog
revision. Imports adopt an available native description only when local metadata
is missing. Re-import, refresh, and native provisioning preserve authored text and
explicitly cleared descriptions. Documentation is stored in the catalog and does
not add unsupported fields to native client configurations.

## Distribution and installation

Release archives target macOS 15+ on arm64/x86_64 and glibc 2.35+ Linux on
arm64/x86_64. Archive names are `kitmux-v0.5.0-OS-ARCH.tar.gz`; `SHA256SUMS` covers
the complete set. Each archive contains the executable and the licenses/notices
for bundled code. Third-party dependencies are statically linked; platform system
libraries remain dynamic. The Linux TUI requires installed terminfo data. Git is
needed for repository skill downloads, but Python/Node and development libraries
are not runtime requirements.

The [README installer](../README.md#download-and-install) detects the target,
downloads the selected release, checks the checksum and executable version, then
atomically installs to a stable path. Upgrades retain one previous binary for
rollback. A failed download, checksum, version check, or staged install preserves
the installed executable. Existing symlink installations require their original
installer. The README also includes an agent prompt for installation, import,
migration checks, conflict handling, and validation.

The release workflow requires ordinary and sanitizer suites on all four targets,
dependency/architecture checks, and clean-runtime smoke tests. Manual runs produce
artifacts/checksums; matching tags publish the complete set after all checks pass.
Exact observed verification is recorded in [IMPLEMENTATION.md](IMPLEMENTATION.md).
Native-client qualification remains opt-in; the Claude subagent probe still
requires its macOS sandbox. Linux release qualification does not claim an
equivalent isolated Claude native probe.

## Upgrade and rollback

V0.4 catalogs need no migration for v0.5. Older mixed-group catalogs still use
`group migrate --preview` and `group migrate --apply`, with their existing backups.
Keep schema-3-compatible binaries for rollback. Binary replacement does not revert
catalog edits or native ownership; use the normal preview/apply restore commands
for configuration recovery. Restart coding clients after replacing the executable
so managed bridge processes load the intended version.

Historical tags point to version-bearing commits: v0.3.0 and v0.3.1 are backfilled,
and the existing v0.4.0 tag is retained. Earlier v0.1/v0.2 development notes predate
this repository's initial v0.3.0 commit; no distinct source revisions exist here
to tag as those releases.
