V0.3 groups can mix all three resource types. Global off and an explicit per-client off override group membership. An enabled assigned group makes a compatible definition available; it does not automatically grant the subagent additional MCPs, skills, or permissions.

Your custom subagents become managed resources.

03 / v0.3 definition management

Manage a profile: create · import · edit · duplicate · group · assign clients · enable / disable · remove · preview / restore.

Share instructions and intent, with native variants where needed. Unsupported models, permissions, or resource mappings must be flagged for review. Membership never silently expands access; a prompt alone does not enforce a sandbox.

Clients and subagents are different.
Clients are Codex, Claude Code, and OpenCode. Subagents are the reusable custom profiles you manage and assign to those clients.

Import the definitions you already use.
Preview discovered profiles, their source and scope, and any conflicting names before adoption. Preserve per-client variants and originals for restore.

Keep commands equally capable.
Every screen action has a CLI equivalent, with plain output and JSON for scripts.

Make availability explicit.
Show available, disabled, incompatible, or refresh required. Loaded skills and running subagent work keep their existing native context.

V0.3 COMMANDS
kitmux subagent import --from codex,claude,opencode --preview
kitmux subagent add code-reviewer --from ./code-reviewer.md \
  --description "Review code changes"
kitmux group include engineering subagent:code-reviewer
kitmux subagent disable code-reviewer --agent claude
kitmux sync --preview
